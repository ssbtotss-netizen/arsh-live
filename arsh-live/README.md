# B6O6 Streaming — منصة صنّاع المحتوى

منصة تعمل أثناء البث المباشر وفيها: قوائم الترتيب، والسبثون، ومؤقتات البث، وروابط OBS. تشتغل مع OBS و TikTok LIVE Studio.
كل عنصر على الشاشة مستقل بمعرّفه وإعداداته وموقعه، وتعديل أي عنصر ما يأثر على الباقي.

## التشغيل
المتطلبات: Node.js 20 أو أحدث، و PostgreSQL.
```bash
docker compose up -d          # قاعدة PostgreSQL محلية (أو استخدم قاعدة جاهزة)
cp .env.example .env
npm install
npx prisma db push
npm run dev                   # http://localhost:3000 ← سجّل حساباً جديداً
```

## البنية: ثلاث محركات منفصلة
| | الملف | الدور |
|---|---|---|
| استقبال الأحداث | `src/server/tiktok.ts` | ربط TikTok LIVE وتوحيد الأحداث (هدية، إعجاب، تعليق، متابعة، اشتراك) مع معرّف لكل حدث + قائمة الهدايا الحقيقية |
| الغرفة | `src/engine/room.js` | منع التكرار ثم توزيع الحدث على المحركين |
| محرك القوائم | `src/engine/leaderboard.js` | سلة مستقلة لكل قائمة. نقاط الإعجاب ما تختلط بنقاط الهدايا |
| محرك الوقت | `src/engine/clock.js` | السبثون والمؤقتات. التوقيت من الخادم، والوقت محفوظ كوقت انتهاء مطلق |
| الرسم | `src/engine/view.js` + `src/styles/overlay.css` | نفس كود الرسم في المحرر والمعاينة وروابط OBS |
| الخادم | `src/server/live-hub.ts` + `server.ts` | غرف WebSocket، ونبضة كل ثانية، والحفظ في PostgreSQL، والاستعادة بعد إعادة التشغيل |
| لوحة التحكم | `dashboard-src/` → `public/b6o6-dashboard.js` | تُبنى من نفس المحركات: `python3 dashboard-src/build.py` |
| روابط OBS | `src/app/overlay/[token]` | خلفية شفافة، وإعادة اتصال تلقائية، ولقطة كاملة عند كل اتصال |

## الدونيشن والتبرعات
محرك مستقل في `src/engine/donations.js`، ومنفصل تماماً عن نقاط هدايا TikTok. كل عملة تُحسب لوحدها، فلا نجمع عملات مختلفة في رقم واحد.

| المزود | الطريقة الرسمية | الحالة |
|---|---|---|
| ميسّر Moyasar (سعودي) | صفحة تبرع `/donate/<slug>` + التحقق من الدفعة عبر API + Webhook (`payment_paid` و`payment_refunded` و`payment_voided`) | مدعوم |
| Streamlabs | Socket API بتوكن صانع المحتوى | مدعوم. لا يرسل أحداث الاسترجاع |
| StreamElements | Astro `channel.tips` (JWT / OAuth2 / Overlay Token) | مدعوم |
| StreamPay، PayPal المباشر، Ko-fi | — | غير مدعوم حالياً |

- **منع التكرار:** القيد `unique(provider, providerId)` يمنع تسجيل نفس العملية مرتين، فيُحتسب رجوع ميسّر والـWebhook لنفس الدفعة مرة واحدة.
- **المدفوعات المعلّقة:** لا تُحتسب.
- **التحقق من مبلغ ميسّر:** نطابق المبلغ مع «نية التبرع» المحفوظة على الخادم.
- **الاسترجاع:** يُخصم من الإحصائيات والأهداف والقوائم، ويبقى في السجل للمراجعة.
- **حماية المفاتيح:** المفاتيح مشفّرة بـ AES-256-GCM عن طريق `APP_SECRET`، ولا تصل للمتصفح ولا لروابط OBS.
- **بيانات الداعم:** البريد الإلكتروني للداعم لا يُمرَّر أبداً.
- **سجل العمليات:** في `AuditLog`.
- **التبرعات التجريبية:** تُعلَّم `test`، ولا تُحفظ في قاعدة البيانات، ولا تدخل الإحصائيات المالية.
- **الفترات:** «اليوم» و«الأسبوع» و«الشهر» تُحسب بالمنطقة الزمنية وبداية الأسبوع اللي يحددها صانع المحتوى.
- **عناصر البث:** شريط الدعم، وهدف الدعم (21 شكلاً)، وآخر داعم، وأكبر داعم (البث الحالي / اليوم / الأسبوع / الشهر / جميع الأوقات)، وقائمة أفضل الداعمين، والتنبيهات بقائمة انتظار وفئات مبالغ.
- **اعتماديات:** `socket.io-client@2` (يتوافق مع خادم Streamlabs).
- **إعداد ميسّر:** حدّد إصدار نموذج الدفع في `MOYASAR_FORM_JS` و`MOYASAR_FORM_CSS` حسب توثيق ميسّر الحالي.

## حساباتي وحسابات الألعاب
- **المحرك:** `src/engine/socials.js`.
- **المنصات المدعومة:** 12 منصة تواصل + منصة مخصصة، و14 لعبة + لعبة مخصصة، ولكل لعبة حقولها وصيغة معرّفها (Riot ID#Tag، Activision ID، Player ID…).
- **التصاميم:** 12 تصميماً بأشكال مختلفة.
- **الحركات:** 14 دخولية، وتُعكس للخروج. تستخدم التحويلات والشفافية فقط، فتكون خفيفة على OBS.
- **التدوير:** حتمي من وقت البدء، فكل الروابط تعرض نفس الحساب في نفس اللحظة.
- **العرض عند الطلب:** رسالة `fx` يبثها الخادم لكل روابط الغرفة.
- **عناصر الاستوديو:** حساب واحد أو تدوير أو عند الطلب، وشريط متحرك، ولوحة لكل الحسابات.
- **الروابط:** رابط مستقل لكل حساب: `?acc=<id>`.
- **الشعارات:** لا نرسم شعارات المنصات أو الألعاب. يظهر رمز نصي بلون المنصة، ويرفع صانع المحتوى الشعار الرسمي بنفسه.

## محرك التناوب (Social Rotation Engine)
- **حالات كل خانة:** دخول ← ظهور ← خروج ← انتظار، مع حالة إيقاف مؤقت.
- **حساب واحد فقط على الشاشة:** الحساب التالي لا يبدأ دخوله قبل ما ينتهي خروج اللي قبله.
- **الإعدادات الافتراضية:** ظهور 5 ثوانٍ، ودخول 0.6 ثانية، وخروج 0.5 ثانية، وانتظار 0.3 ثانية.
- **تزامن الروابط:** التوقيت حتمي من `startedAt`، فكل روابط OBS متزامنة.
- **التحكم:** التالي والسابق والإيقاف المؤقت تُزيح وقت البدء بدل ما تعيد التشغيل. حتى الترتيب العشوائي ثابت في كل الروابط.
- **التصاميم:** 50 تصميماً في `SOCIAL_DESIGNS` يولّدها `socialDesignCSS()`. تختلف في الشكل، والتوزيع، وموضع الشعار وشكله، والخلفية، والإطار، والأبعاد، والمؤثر.
- **الحركات:** 30 دخولية، و20 خروجاً، و10 حركات أثناء الظهور. اللمعة البيضاء قابلة للتخصيص في الاتجاه والسرعة والعرض والزاوية والقوة والتكرار، ولها نسخ ذهبية وفضية وزرقاء.
- **الأداء والوصول:** الحركات خفيفة (transform وopacity وclip-path)، وتحترم إعداد `prefers-reduced-motion`.

## السبثون
- **مصادر إضافة الوقت:** الهدايا (بجدول قابل للتعديل بالمعرّف أو بالاسم أو بحد أدنى من الألماس، أو قيمة لكل ألماسة)، وكل N إعجاب، والمتابعة، والاشتراك، وتحقيق هدف، والإضافة والخصم يدوياً. وكل طريقة تتفعّل لوحدها.
- **الحدود:** حد أقصى للوقت المتبقي، وحد لمجموع الإضافات، وحد أدنى عند الخصم، وبدء مجدول.
- **إيقاف تلقائي:** يتوقف عند انقطاع البث ويكمل عند رجوعه، وهذا قابل للتعطيل من الإعدادات.
- **منع التكرار:** معرّف الحدث من TikTok يُحفظ، والقيد `unique(userId, eventId)` يمنع تسجيل نفس الحدث مرتين، وتُستعاد المعرّفات بعد إعادة تشغيل الخادم.
- **السجل:** كل عملية تُحفظ في `SubathonLog`.
- **أحداث وضع التجربة:** ما تدخل سجل الهدايا الحقيقي.

## قيود TikTok
مكتبة `tiktok-live-connector` **غير رسمية** وممكن تتوقف إذا غيّر TikTok نظامه. الإعجابات تصل على دفعات. الاشتراكات تصل فقط للحسابات المفعّل لها الاشتراك. ودعم اليوم والأسبوع والشهر يُحسب من الأحداث اللي سجّلتها المنصة فقط.

## النشر
يحتاج خادم يبقى شغّالاً ويدعم WebSocket، مثل VPS أو Railway أو Render أو Fly.io، مع PostgreSQL وHTTPS. Vercel ما يدعم الخادم المخصص.

## قوائم Pro الشفافة وأهداف الدعم المصغّرة
- عنصر **قائمة ترتيب Pro** (`lb`): خلفية خارجية شفافة 100%، مصدر بيانات قابل للاختيار: نقاط الهدايا، عدد الهدايا، هدية محددة (`giftBy`)، التكبيس، الدونيشن، أكثر المتفاعلين، أكثر المعلقين.
- تخطيط حقيقي لكل عدد: 1 بطل، 3 منصة تتويج (الأول بالوسط ومرتفع)، 5 منصة + صفوف، 10 مضغوط (أول 3 أكبر)، 20 عمودان.
- عدّ تصاعدي للأرقام، انتقال ناعم عند تغيّر المراكز، تاج متحرك، لمعة ذهبية واحتفال قصير عند تغيّر الأول، نبض الأيقونة عند الزيادة، لمعة بيضاء تحت النص.
- ألوان المراكز الخمسة، شفافية الصفوف، شكل الصور، الخط — قابلة للتعديل، مع «حفظ تصميمي» و«استعادة الافتراضي».
- مكتبة «🎨 مكتبة تصاميم القوائم»: 7 فئات، بحث، مفضلة، معاينة حيّة، تطبيق بضغطة. مكتملة: 100 تصميم في 7 فئات (الدائرية والهالات 1–15، السحابية والحالمة 16–25، الملكية والفاخرة 26–40، النيون والألعاب 41–55، الزجاجية والكريستالية 56–70، ثلاثية الأبعاد 71–85، الصغيرة والأنيقة 86–100). المعاينات خارج الشاشة تتوقف حركتها لتخفيف الحمل.
- **هدف دعم مصغّر** (`sgoal`): هدية محددة / نقاط / عدد هدايا / تكبيس / دونيشن / متابعات / اشتراكات / مخصص، مع «ابدأ العدّ من الآن» و10 تصاميم.
- وضع الأداء المنخفض: من إعدادات العنصر أو بإضافة `&lp=1` لرابط OBS. يحترم «تقليل الحركة» في النظام.
- المتابعات والاشتراكات تعتمد على وصول أحداثها من TikTok (الاشتراكات للحسابات المفعّلة فقط).

## استوديو السبثون — قواعد التفاعل ولوحة القوانين
- **محرك قواعد** (`src/engine/clock.js`): قائمة قواعد غير محدودة، لكل قاعدة معرّف مستقل: هدية محددة / متابعة / اشتراك / تكبيس (كل N) / مشاركة / أمر تعليق / دونيشن.
- لكل قاعدة: زيادة أو نقصان، المقدار (ثانية/دقيقة/ساعة)، عدد الهدايا المطلوبة، حد ألماس، انتظار بين التنفيذات، انتظار لكل مستخدم، حد بالدقيقة (حماية السبام)، أقصى تأثير، صوت، الظهور في اللوحة.
- **الدونيشن**: بعد تأكيد الدفع فقط ومرة واحدة: «زيد» يزيد و«نقص» ينقص حسب المبلغ (لكل مبلغ = مدة)، مع إجراء افتراضي بدون كلمة وحد أدنى وعملة.
- الهدايا المتتالية (streak) تُحسب مرة واحدة عند نهايتها بعددها الكامل. الأحداث المكررة تُتجاهل. الوقت لا ينزل تحت الصفر ولا تحت الحد الأدنى.
- **المشاركات**: يستقبل الخادم حدث المشاركة إن أرسلته المكتبة غير الرسمية؛ اللوحة تعرض «غير مؤكدة» حتى يصل حدث حقيقي.
- السجل يحفظ معرّف القاعدة والمستخدم، وأحداث التجربة معلّمة 🧪.
- الإعدادات القديمة تُرقّى تلقائياً بنفس سلوكها، والتعديل بالصيغة القديمة عبر API ما زال يعمل.
- قوالب جاهزة: عادي، تنافسي، الهدايا فقط، الدونيشن فقط، التكبيس فقط، شامل.
- **لوحة قوانين السبثون** (`srules`, `src/engine/rboard.js`): تُقرأ تلقائياً من القواعد المفعّلة، 5 أوضاع (قائمة، تناوب، شريط أفقي/عمودي، بطاقات، مختصرة)، وميض القانون عند تنفيذه، ألوان الزيادة والنقصان، إخفاء قوانين محددة، تحكم بسرعة وتشغيل التحريكات. التصاميم المنفذة: 10 من 40.

## أهداف الدعم التفاعلية 2.0 (`src/engine/vgoal.js`)
- محرك تعبئة موحّد: الشكل يُملأ فعلياً بنسبة التقدم (650/1000 = 65%). الأنواع المنفذة: سائل من الأسفل، قطعة قطعة، عملات تتجمع، دائرية مع عقارب الساعة.
- التصاميم المنفذة: كأس الذهب، الألماسة المتكوّنة، صندوق الكنز (خشب ← فضة ← ذهب ← ألماس مع فتح الغطاء)، الساعة الدائرية.
- مراحل قابلة للتعديل (افتراضي 25/50/75/90) مع رسالة عند كل مرحلة واحتفال عند 100%.
- عند كل دعم: رسالة «🦁 محمد +1 أسد»، عدّ تصاعدي، آخر داعم بصورته، أكبر مساهم وعدد المساهمين (من البيانات المحفوظة)، وتأثير قابل للاختيار (8 حالياً).
- المصادر: هدية محددة، نقاط، عدد هدايا، تكبيس، دونيشن، متابعات، اشتراكات، مشاركات (غير مؤكدة)، مخصص.
- مكتبة الأهداف: شريط تجربة 0–100%، دعم تجريبي، تجربة الاكتمال، تصنيف بالمجموعات العشر.

## مركز البوتات والذكاء الصوتي (`src/engine/bots.js`, `botview.js`)
- يعمل داخل الغرفة نفسها (الخادم في البث الحقيقي، لوحة التحكم في التجربة) → كل رد يُولَّد مرة واحدة ويُبث لكل الروابط.
- الأوامر (`!وقت` `!تكبيس` `!هدف` `!متصدر` `!مكبس` `!حساباتي` `!روبلوكس` `!دعم` + مخصص) بمتغيرات حية من السبثون والأهداف والقوائم والحسابات؛ المتغير الغائب = نص بديل (لا قيم وهمية). صلاحيات وانتظار عام/لكل مستخدم.
- ردود تلقائية: يحتوي/مطابق/يبدأ/Regex، تجاهل الهمزات والتشكيل، ردود متعددة عشوائية، مرة لكل مستخدم، حد بالدقيقة.
- شكر الهدايا (رسائل خاصة لهدايا محددة + حد أدنى) والدونيشن المؤكد وأول دعم، المتابعات والاشتراكات، الترحيب عند الدخول (حدث member — غير مؤكد).
- رسائل دورية بالتسلسل/عشوائي مع شروط: نشاط الشات، مهلة بعد آخر رد، حد بالبث، إيقاف بعد دعم كبير، وتعمل أثناء البث المتصل فقط.
- القارئ الصوتي: 9 أوضاع، فلترة (كلمات، مستخدمون، روابط، أرقام، تكرار)، قائمة انتظار بأولويات وصلاحية ومنع تكرار وعدالة، موافقة يدوية، 20 قالباً صوتياً، أصوات المتصفح (Web Speech).
- مشغّل صوت واحد فقط (قفل بين النوافذ؛ رابط القارئ `&voice=1` له الأولوية) — لا يُقرأ التعليق مرتين.
- لا إرسال إلى شات TikTok (غير مصرّح): المخرجات في عنصر «ردود البوت» الشفاف + صوت + نسخ للإرسال اليدوي.
- الإعدادات محفوظة لكل مستخدم (حقل `bots`) وتُحمَّل على الخادم حتى مع إغلاق لوحة التحكم.
- لم يُنفَّذ بعد: بوت الذكاء الاصطناعي (يحتاج مزوداً على الخادم)، أصوات TTS طبيعية/سعودية (تحتاج مزوداً)، 40 تصميماً للتعليقات (3 حالياً لعنصر الردود)، محرر القواعد «عندما ← إذا ← نفّذ».

## مكتبة الأهداف الأسطورية (`src/engine/vgoal80.js`)
- الدفعة الأولى (10/80): النخلة والسيفان (مستوحى)، النخلة الذهبية، الدلة السعودية، الصقر الملكي، الدرعية التاريخية، صندوق الكنز الملكي، التنين الأسطوري، مفاعل الطاقة، كأس B6O6 الملكي، البطة الذهبية B6O6.
- محرك التعبئة الموحّد صار عاماً: أجزاء تضيء (`vg-fc`)، سائل (`vg-liq` بحدود من data-top/bot)، عملات (`vg-pile`)، غطاء (`vg-lid`)، حلقة (`vg-arc`). إضافة تصميم = رسم + CSS عبر `vgRegister`.

## عداد المتابعين المباشر (`src/engine/followers.js`, `fcview.js`)
- الحالة في `C.followers[platform]` (تُحفظ مع حالة الغرفة). الرقم «موثّق» فقط من API رسمي؛ غير ذلك «تقديري» = عدد يدوي + متابعات البث المؤكدة.
- متابعات الاختبار تُحفظ منفصلة في `test` وتُعرض فوق الرقم فقط، وتُمسح بزر «مسح التجربة» أو عند تعيين العدد.
- الهدف: `progress = clamp((current - start)/(target - start)*100, 0, 100)` مع نقطة بداية (`goalStart`) ومراحل (`goalStages`) أو زيادة ثابتة (`goalStep`).
